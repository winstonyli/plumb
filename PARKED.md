# Parked work

The one list of deferred work (format: `~/.claude/VERSIONING.md`). Delete an item when it is fixed. Each entry carries its own evidence; check it before acting on one.

- **Poll the Processes view every 2 s while the window is in the background.** `POLL` is 1 s (`crates/plumb/src/window/procs.rs:14`). *Why parked:* halves the visible cost but changes what "live" means, so it wants the user's say. *Trigger:* idle CPU over the 1 % target again (measured 0.73-1.67 % of one core on 2026-10-31, runs `idle-*` and `idle2-*` in `docs/runs.md`; the kernel call costs 10-14 ms per snapshot), or a request for it. *Evidence:* `docs/superpowers/specs/2026-10-16-plumb-views-design.md` (Cost). *Status:* parked. A minimised window already stops the poller (`follow_processes`).
- **Restart Manager "Who is using this" opens one session per call.** `holders` starts and ends its own session (`crates/plumb-scan/src/holders.rs:29-32`), so a large selection is looked up sequentially. *Why parked:* it is one path at a time today. *Trigger:* a multi-path lookup (the delete failure dialog on many files) that feels slow. *Fix:* register all paths in one session. *Status:* parked.
- **Mica window backdrop.** *Status:* decided against. It conflicts with plumb's opaque Direct2D painting, and the themed frame already follows the Windows accent colour.
- **A Copy button on the who-is-using modal.** The modal lists `PID  name` lines with only Close (`Modal::holders`, `crates/plumb/src/modal.rs`). *Why parked:* declined for the first version; the list is short and readable. *Trigger:* a request to paste the holders into a report or a search. *Status:* parked.
- **Keyboard accelerators on the modal buttons** (R, D, U, C by first letter, drawn underlined). *Status:* decided against for now. Enter, Esc, Tab, arrows and clicks cover it, and a one-key "Delete permanently" should stay deliberate. *Trigger:* a request for it; if taken, leave the accelerator off "Delete permanently". Typed characters already reach `modal_input` as `Edit::Char`.
- **Live check of the light theme, a real failed delete and the title bar accent.** Verified offscreen (render tests, the failure-notice shots) but not on screen in 0.9.0 (not checked in 0.10.x either). *Why parked:* by decision, 2026-10-18. *Trigger:* the next live session, or a visual report. *Evidence:* v0.9.0 shipped on render tests and selftests only. *Status:* parked.
- **Live check of the Recycle prompt on removable and network drives, and Explorer's Ctrl+Z.** The shell's own "too big for the Recycle Bin" prompt stays native (`crates/plumb/src/trash.rs`). *Why parked:* by decision, 2026-10-18; needs a removable or network drive on hand. *Trigger:* a drive to test with, or a report of a wrong prompt or a failed undo. *Status:* parked.
- **A file tile's "modified … , today" compares UTC days.** `tile_tip` passes `map_now = today()` (a UTC day) and the tree stores mtimes only as UTC day counts (`Tree::mtime`; `tile_tip` and `today` in `crates/plumb/src/app.rs`), so within a few hours of local midnight an age can read a day off ("today" for yesterday evening, or the reverse). The Processes tooltip does not have this (it keeps the FILETIME and uses `fmt::local_day`). *Why parked:* fixing it needs the time of day in the tree (a wider mtime field in every node) or a per-view local-day shift of both numbers, for a tooltip's age. *Trigger:* a seen wrong "today"/age near midnight, or a reason to widen `mtime` anyway. *Evidence:* 2026-10-30. *Status:* parked.
- **The release notes carry only the tagged version's changelog section.** `release.yml` reads the one `## x.y.z` section, so v0.10.1, which superseded the unpublished v0.10.0, shipped with a notice pointing at a section the Release page did not show (the body was edited by hand on 2026-10-31). *Why parked:* it happens only when a tag is superseded before publishing. *Trigger:* the next superseded tag; then have the workflow append the sections of every tag since the last published release. *Evidence:* `.github/workflows/release.yml`, v0.10.1 release, 2026-10-31. *Status:* parked.
- **Idle memory under 30 MB.** The spec's target is not reachable with a hardware D3D device: about 27 MB of the idle footprint is the AMD user-mode driver loaded by creating it, and plumb's own share is a few MB. The WARP software device would meet it (2.7 MB). *Why parked:* WARP draws on the CPU and breaks the spec's "adapter that owns the monitor" decision, for a mostly static UI. *Trigger:* a memory complaint, or a reason to drop the hardware adapter choice. *Evidence:* `docs/benchmarks.md` "Where the idle memory goes" (2026-10-11). *Status:* parked.
- **Per-view state as `Vec<Slot>` with an active index, no swapping (A1's g2).** `in_slot` would become "point `active` at that slot", and the `borrowed` swap would go. *Why parked:* every `self.tree` becomes an indexed access through `&mut self`, so most `App` methods would take a slot; decided 2026-10-31 to do the one-struct swap first (`docs/superpowers/specs/2026-10-31-view-slot-design.md`). *Trigger:* A1 landed; revisit then (the user asked). *Status:* held for A1.
