# Parked work

The one list of deferred work (format: `~/.claude/VERSIONING.md`). Delete an item when it is fixed. Evidence verified against the code on 2026-10-17.

- **Poll the Processes view every 2 s while the window is in the background.** `POLL` is 1 s (`crates/plumb/src/window/procs.rs:14`). *Why parked:* halves the visible cost but changes what "live" means, so it wants the user's say. *Trigger:* idle CPU over the 1 % target again (measured 1.09-1.22 % on 2026-10-16; the kernel call costs 10-14 ms per snapshot), or a request for it. *Evidence:* `docs/superpowers/specs/2026-10-16-plumb-views-design.md` (Cost). *Status:* parked. A minimised window already stops the poller (`follow_processes`).
- **A process's own memory is invisible in the map.** `treemap::fill` lays out `subtree_size - size` (`crates/plumb-core/src/treemap.rs:187`), so a parent shows only its children's share. *Why parked:* needs a node that is both a tile and a folder. *Trigger:* a parent whose own memory matters (a browser's main process) read as too small. *Status:* parked.
- **Working-set memory counts shared pages once per process.** A family and the total can exceed physical use (`working_set`, `crates/plumb-scan/src/procs.rs:16`). *Why parked:* private bytes would avoid it but is commit, not resident. *Trigger:* a report of totals that exceed RAM, or a decision to offer private bytes as a metric. *Status:* parked.
- **Restart Manager "Who is using this" opens one session per call.** `holders` starts and ends its own session (`crates/plumb-scan/src/holders.rs:29-32`), so a large selection is looked up sequentially. *Why parked:* it is one path at a time today. *Trigger:* a multi-path lookup (the delete failure dialog on many files) that feels slow. *Fix:* register all paths in one session. *Status:* parked.
- **The Processes tooltip's start time uses the UTC day.** `fmt::date(day)` with `today()` (`crates/plumb/src/app.rs:695`). *Why parked:* cosmetic, off by at most a day near midnight. *Trigger:* a seen wrong date. *Status:* parked.
- **The Files held list cannot scroll or refresh.** It shows the first lines that fit (`held_text`, `crates/plumb/src/app.rs:755`). *Why parked:* the first version is a glance, not a browser. *Trigger:* a process holding more files than fit, where the rest matters. *Status:* parked.
- **Mica window backdrop.** *Status:* decided against. It conflicts with plumb's opaque Direct2D painting, and the themed frame already follows the Windows accent colour.
- **A Copy button on the who-is-using modal.** The modal lists `PID  name` lines with only Close (`Modal::holders`, `crates/plumb/src/modal.rs`). *Why parked:* declined for the first version; the list is short and readable. *Trigger:* a request to paste the holders into a report or a search. *Status:* parked.
