- **The release notes carry only the tagged version's changelog section.** `release.yml` reads the one `## x.y.z` section, so v0.10.1, which superseded the unpublished v0.10.0, shipped with a notice pointing at a section the Release page did not show (the body was edited by hand on 2026-10-31). *Why parked:* it happens only when a tag is superseded before publishing. *Trigger:* the next superseded tag; then have the workflow append the sections of every tag since the last published release. *Evidence:* `.github/workflows/release.yml`, v0.10.1 release, 2026-10-31. *Status:* parked.
- **Idle memory under 30 MB.** The spec's target is not reachable with a hardware D3D device: about 27 MB of the idle footprint is the AMD user-mode driver loaded by creating it, and plumb's own share is a few MB. The WARP software device would meet it (2.7 MB). *Why parked:* WARP draws on the CPU and breaks the spec's "adapter that owns the monitor" decision, for a mostly static UI. *Trigger:* a memory complaint, or a reason to drop the hardware adapter choice. *Evidence:* `docs/benchmarks.md` "Where the idle memory goes" (2026-10-11). *Status:* parked.
- **Per-view state as `Vec<Slot>` with an active index, no swapping (A1's g2).** `in_slot` would become "point `active` at that slot", and the `borrowed` swap would go. *Why parked:* every `self.tree` becomes an indexed access through `&mut self`, so most `App` methods would take a slot; decided 2026-10-31 to do the one-struct swap first (`docs/superpowers/specs/2026-10-31-view-slot-design.md`). *Spike 2026-10-31 (throwaway branch, reverted):* indexing through `slot()`/`slot_mut()` accessors in `App` alone left at least 21 borrow conflicts in 10 functions, mostly one shape: `(&self.slot().tree, &mut self.slot_mut().model)` (the tree read while the rows are updated), plus 83 sites that needed `slot_mut()`; each conflict is a local restructure (take `&mut Slot` once and destructure), not a rename, and borrowck had not yet run on the functions that failed type checking, so the count is a lower bound. After A1 a swap is one `mem::swap`, so the gain is small. *Trigger:* a third kind of per-view state that cannot live in `Slot` or `Run`, or a reason to hold several views on screen at once. *Status:* decided against.

- **"Unreadable" counts every folder the walker could not list, not only access-denied ones.** The scan summary says "N folders unreadable" from `NodeFlags::DENIED`, which `walk.rs` sets on any read error (a path too long or a dropped network share looks the same as a permission refusal), so the hover cannot say which. *Why parked:* telling them apart needs a new node flag or reason set by the scanner and carried through `plumb-core`. *Trigger:* a report of a misleading count, or wanting the reason per folder. *Evidence:* `crates/plumb-scan/src/walk.rs:230`, `crates/plumb/src/window.rs` `scan_done`, 2026-11-10. *Status:* parked.
- **Stale and Load scores do not age or re-sample while a window stays open.** A file's age is measured against the clock set when its tree was built (`Tree::set_now`), so a view left open for days keeps its scores; the Processes load follows each snapshot. *Why parked:* by decision 2026-11-11 (one clock per tree keeps the sums exact). *Trigger:* a stale score reported after days open; then re-set the clock on a rescan or on a timer and rescore. *Evidence:* `crates/plumb-core/src/tree.rs` `set_now`/`rescore`, `crates/plumb-core/src/score.rs`. *Status:* parked.
- **`IO_FULL` is fixed at 500 MB/s.** The Load column's I/O share divides by this constant, not by the disk's measured speed. *Why parked:* by decision 2026-11-11, to keep the score a plain share with no probing. *Trigger:* a process that reads at NVMe speed and still shows a low Load. *Evidence:* `crates/plumb-core/src/score.rs` `IO_FULL`. *Status:* parked.
- **Modified time is a weak proxy for "unused".** The Stale column weighs a file by `LastWriteTime` only; Windows keeps no reliable last-access time (it is off by default), and a file that is read daily but never written looks stale. *Status:* decided against 2026-11-11 (no access time, no usage tracking); the column says "not modified", and its tooltip says so.
