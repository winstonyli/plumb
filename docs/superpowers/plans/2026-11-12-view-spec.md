# One descriptor per view kind: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline; the three tasks share `app.rs` and `draw.rs`). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Per-kind column data lives in one const table per `ViewKind`, `Layout` flags are derived in one place, and saved sort and widths belong to a view kind and name columns by a stable id.

**Architecture:** `view_spec.rs` holds `ViewSpec`/`ColSpec`/`ColId` and two consts; `ViewKind::spec()` reaches them and the seven `ViewKind` methods go. `App::layout_now()` builds the `Layout` flags. `State` stores `disk` and `processes` tables keyed by `ColId`; `App` holds both kinds' sort and widths and swaps the working copy on a kind change.

**Tech Stack:** Rust workspace (`plumb`, `plumb-core`, `plumb-scan`), serde/toml, Direct2D drawing.

**Spec:** `docs/superpowers/specs/2026-11-11-view-spec-design.md` (decisions g1 per-kind tables keyed by `ColId`, i1 three commits, k1 table data only). Cleanup items A1, A2, A5.

## Global Constraints

- No change to what any view shows or does; render tests and selftest output are identical after Tasks 1 and 2.
- Behaviour stays `kind() == Processes` code (k1): menu, kill, suspend, held files, map tiles, tips, status, spawn.
- Name and % of parent cells stay drawn by `draw.rs`; alignment and dimness follow column position (Score in `fg`, Size/third/fourth in `side`).
- No migration shim: an old `state.toml` parses to defaults for sort and widths (one-time reset).
- Version bump, tag and push only on the user's request; the changelog needs an upgrade note for the reset.
- Each task ends with `cargo test --workspace` and `cargo clippy --workspace --all-targets` clean, one commit per task. Builds: if a running `plumb.exe` locks `target\`, use `CARGO_TARGET_DIR="$TEMP/plumb-target"`.

## Review Focus

- A state file written by 0.13.0 (top-level `sort` and `columns`) loads without error and gives defaults (Task 3 test).
- Switching Disk to Processes and back restores each kind's own sort and widths, and a sort click in one does not move the other (Task 3 test).
- `restore()` runs before any view is active: both kinds' prefs must be applied then (Task 3 test).
- A saved `ColId` that the kind does not have (e.g. `cpu` under `[disk]`) is ignored, not a panic (Task 3 test).
- The "at least" marker and the Score tooltip are unchanged during a scan (Task 1: existing render tests).
- Kind changes happen at five sites (begin_scan, park, unpark, in_slot twice): each must carry the prefs; a column drag then a switch is not lost; remembered() reads the live widths (Task 3 tests).
- The banner is right after set_live (assign slot.live first) and layout_now leaves layout.toast alone (Task 2 test).

## End-state fit

`view_spec.rs` (new) owns per-kind column data; `app.rs` owns `layout_now` and the per-kind prefs; `state.rs` owns the stored shape. Replaces: the seven `ViewKind` methods (`titles`, `score_text`, `score_help`, `size_text`, `sort_key`, `class_label`, `last_two`), `COL_THIRD`/`COL_FOURTH`, `Layout::{with_metric, with_held, with_cancel, with_basket, with_banner}` plus the `metric`/`held` pair (now `procs`), `State.sort`/`State.columns`, `Sort`. Deletes their tests (rewritten as table tests). Leaves in place: the 11 `kind() == Processes` behaviour branches (follow-up A3), `Slot`/`Run` (A4).

### Task 3: Sort and widths per view kind (A5)

`App::kind()` reads `self.active`, and `active` is written outside `swap_slot` at five sites (`app.rs:532` `begin_scan`; `window.rs:534` park via `take()`, `556` unpark, `600` and `602` `in_slot`). So the per-kind swap cannot live in `swap_slot`; it lives in one `set_active`.

**Files:**
- Modify: `crates/plumb/src/state.rs` (`Sort`, `State.sort`, `State.columns`), `crates/plumb/src/app.rs` (`sort` field ~404; `sort()` ~474; `restore` ~479; `remembered` ~495; header click ~1277; column drag ~1206; `begin_scan` ~532; `fresh_model` callers ~571, 587, 606), `crates/plumb/src/window.rs` (the five `active` writes; `remembered()` save ~1758)
- Test: `state.rs`, `app.rs` (rewrite `app.rs:2495-2518`, `state.rs:90-106`)

**Interfaces:**
- Produces: `ColId` (in `view_spec.rs`) derives `PartialOrd, Ord, Serialize, Deserialize` with `#[serde(rename_all = "lowercase")]`. In `state.rs`: `pub struct ViewPrefs { pub widths: BTreeMap<ColId, f32>, pub sort: Option<SortPref> }`, `pub struct SortPref { pub col: ColId, pub descending: bool }`, `State { window, disk: ViewPrefs, processes: ViewPrefs, map }`, all `#[serde(default)]`. `widths` holds the five resizable columns (Score through the last; not Name) and is declared before `sort` so TOML writes the sub-table last. Old top-level `sort`/`columns` keys are ignored.
- In `App`: `prefs: [Prefs; 2]` (indexed by `ViewKind`), `Prefs { sort: (usize, bool), col_w: [f32; 5] }`. `sort()` and the header click read and write `prefs[kind()].sort`. `layout.col_w` is the active kind's working copy: `App::set_active(&mut self, a: Option<usize>)` stores `layout.col_w` into `prefs[kind()]`, assigns `self.active`, then loads `layout.col_w` from `prefs[kind()]` through `set_col_w` (clamped); all five `active` writes call it. `restore(&State)` fills both kinds' `prefs` (ignoring a `ColId` the kind lacks and non-finite widths; widths clamped to `MIN_COL_W..=4000`), then loads the active kind's widths. `remembered()` clones `prefs`, overlays the active kind's live `layout.col_w`, and converts positions to `ColId` through `ViewKind::spec().cols`.
