read-only Sonnet surveys ran on 2026-11-11 at commit `4cbf2fe` (dead code, tests and fixtures, docs and hygiene,

(checked).

### Architecture (principled end state)

**Outcome 2026-11-11:** A1+A2+A5 (own plan after v0.13), A3, A4, A6 and A7 are parked in `PARKED.md` with triggers; A8 stays decided against.

The row table is "one table of six columns, parameterised by `ViewKind`", half data and half hand-indexed `match`es.
Ranked by end-state design:

- **A1. `ViewSpec`: one per-kind descriptor replacing ~25 `ViewKind` branches** (7 methods in `app.rs`; 17 non-test
  `== ViewKind::Processes/Disk` sites counted by hand (checked); draw.rs kind checks): a column table (`title`,
  `sort`, `cell`, `align`, `partial_marker`) plus capability fields. Header loop, row loop, `Header(c)` sorting and
  the score tooltip iterate the table; `COL_THIRD`/`COL_FOURTH` disappear. Cannot subsume the Processes menu/kill
  logic or held-files state. **OWN PLAN** (changes `Scene`, the `ViewKind` API, shared column constants). ~300 lines,
  net about -150.
  **Own plan 2026-11-12** (`docs/superpowers/plans/2026-11-12-view-spec.md`). **Done 2026-11-12**: `view_spec.rs` holds the two const tables; the seven `ViewKind` methods and `COL_THIRD`/`COL_FOURTH` are gone. Not done: the Processes behaviour stays `kind()` branches (spec decision k1; A3 is parked).
- **A2. Derive `Layout` flags from `App` in one place** (`cancel`, `basket`, `metric`, `held`, `banner`, `toast`
  mirrored by hand at ~8 sites): one `layout_now()`. Part of A1's plan. **Done 2026-11-12** (own plan above): `App::layout_now`, `Layout.procs` replaces `metric` and `held`, the `with_*` builders are deleted.
- **A5. Sort and widths per view, keyed by a stable column id.** Today `State.sort.column` means "Items" on a disk
  and "CPU" on processes, and widths are shared. **OWN PLAN** (changes the stored `state.toml` format: a version
  bump, and with it the one-off misalignment on upgrade goes away). Small. Part of A1's plan.
  **Own plan 2026-11-12** (`docs/superpowers/plans/2026-11-12-view-spec.md`). **Done 2026-11-12** with A1 and A2: per-kind tables keyed by column id, `ColId` strings at the file edge, one `set_active`; the next release resets saved sort and widths once (changelog notice).
- **A3. Name the `aux` slots and move the Processes-only methods to `app/procs.rs`**: `aux[2]` hand-indexed at ~10
  sites in 2 crates though `plumb_core::procs::pid` exists; ~250 lines leave the 3263-line `app.rs`; its ~1700 lines
  of tests could move to `app/tests/` by topic. Not an interface change.
- **A4. One per-view state (`ViewState { slot, source: Source::{Disk, Processes} }`) instead of `Slot` + `Run`**,
  deleting `swap_window_fields` and its guard test. **OWN PLAN** (changes the App/Win seam and selftest).
  ~200 lines.
- **A6. Hit-test once per input** (14 calls in `app.rs`). Inside A1's plan.
- **A7. Move pure code from the GUI crate to `plumb-core`** (`fmt.rs`, `describe.rs`, `attrs.rs`, `restore.rs`,
  basket marking, `Metric` labels). **OWN PLAN** (a public API move across crates).
- **A8 (decided against): do not split `window.rs`** (its `wndproc` and `effect()` are inherent dispatch tables;
  A4 is the real fix).
